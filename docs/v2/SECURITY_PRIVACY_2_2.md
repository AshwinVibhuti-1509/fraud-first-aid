# Security & privacy review — local follow-up workspace (2.2)

- **Data origin:** all follow-up fields, status messages, attachment titles, incident dates, and screenshots are user-supplied. No government verification is implemented.
- **Data flow:** casework.js operates in browser memory and contains no `fetch`, XMLHttpRequest, cookies, localStorage, sessionStorage, or external request. Screenshots enter only through the user's file picker, are rendered via `<img src="data:image/...">` and are not transmitted by this module. Separate existing screenshot *analysis* intake sends a user-approved flattened image to the backend if enabled.
- **Image gate:** PNG/JPEG MIME and magic signature, browser decode, up to 2 MB per item, eight items and 8 MB total. Decoded images are not modified or redacted; user should withhold screenshots containing secrets. Browser-specific image decoder vulnerabilities remain outside this app's review.
- **Rendering:** user strings are displayed using DOM `textContent` rather than `innerHTML`. Imported images are checked for PNG/JPEG data URI, magic signature and byte length. No HTML injection accepted as an attachment.
- **Persistence:** none until the explicit JSON export. Images included in exported case pack are plain base64, **not encrypted**; users should protect local files. File deletion within browser tab does not remove earlier exports. The app does not claim otherwise.
- **Import:** schema ID and collection cardinalities are checked; body size limited to 13MB; individual attachment types, base64, length, magic and user-text lengths validated; existing session is not changed on validation errors. Imports do not re-enter official services or rebuild the plan automatically.
- **No official account access:** government OTP, CAPTCHA and identity documents must stay on official government site. Tracker is a separate browser link with no embedded data.
- **Limitations / remaining review:** no malicious-file AV scan, encrypted backups, independent pen test, authenticated government APIs, broad accessibility or Windows acceptance. Browser test runs in a local synthetic environment. No production-user uploads recommended before an independent security review.
